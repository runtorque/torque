    Testing¶

    Loom's automated coverage is intentionally layered. Most confidence should come from Python unit and integration tests, with only a thin UI/state smoke layer for frontend regressions.

    Baseline Stabilization¶

    Before expanding coverage, the suite needed one explicit cleanup:

    • tests/test_worktree_gitignore.py had drifted from the current product behavior. loom/worktree.py only writes .loom/worktrees/ to .gitignore; Loom-injected local files belong in .git/info/exclude. The test now matches that contract so the baseline can go green before broader coverage expansion.

    Running Tests¶

    Use the repo entrypoint:

    make test

    This runs the Python regression suite with:

    python3 -m unittest discover -s tests -v

    If the tests-implementation-wave frontend regression files are present, they run through the Python suite as part of that same entrypoint.
